# 串口通信与接收助手（2026-11-08）

## 怎么使用

双击项目根目录 **启动串口助手.cmd**。无需 Docker，无需重新训练。

1. 默认自动开启“本机模拟”接收。没有下位机时保持这个模式，COM1 选择框此时不起作用。
2. 点击 **启动摄像头识别**，打开 USB 摄像头识别并向助手发送实时结果，默认摄像头编号 0。
3. 或点击 **回放历史识别结果**，循环发送之前实际生成的双土豆识别日志；界面明确标注“不是当前摄像头”。回放中的时间、FPS 和推理耗时来自原日志，不能当作当前测量。
4. 切换前先点 **停止发送**。摄像头窗口也可以按 Q 退出。
5. **关闭接收**只关闭接收端。发送程序仍运行时会等待重连。关闭整个助手会同时停止它自己启动的发送程序。

表格显示 ID、物品、垃圾大类、框左上角、宽高和置信度。速度尚未接入，显示“未启用”，通信中为 `null`，不能解释为静止速度 0。没有目标时发送空列表；超过 2 秒没有新数据，清空当前目标，保留历史文本供查看。

当前系统只有 COM1，没有互连的虚拟 COM 对。默认以 **127.0.0.1 本机 TCP**连接两个真实进程，使用正式数据协议；它不是物理串口，不能验证波特率、UART 接线和下位机。发送端使用 pySerial `socket://`，以后改为 `COM5` 等实际端口名即可沿用协议。pySerial 文档说明 socket 模式仅传输数据，忽略串口配置：[URL Handlers](https://pyserial.readthedocs.io/en/latest/url_handlers.html#socket)。

## 程序与输出

| 文件 | 用途 |
|---|---|
| `scripts/serial_assistant.py` | 中文助手；接收、显示，启动识别或回放 |
| `scripts/run_live.py` / `src/invc_vision/app.py` | 摄像头检测、独立跟踪，生成识别记录 |
| `src/invc_vision/telemetry.py` | 完整本地日志及发送入口 |
| `src/invc_vision/serial_sender.py` | 后台发送、限频、保持最新结果、断线重连 |
| `src/invc_vision/protocol.py` | 数据格式、CRC、增量解析、序号统计 |
| `src/invc_vision/serial_receiver.py` | 助手和命令行共用的接收实现 |
| `scripts/serial_monitor.py` | 命令行接收 |
| `scripts/replay_serial.py` | 用相同发送器发送历史识别日志 |

每次助手会话生成 `outputs/serial/assistant_日期_时间/`：

- `receive_时间/received.jsonl`：通过校验的接收包、接收时间、序号状态。
- `receive_时间/summary.json`：接收数量、错误统计、最后数据。
- `camera_时间.jsonl` 或 `replay_时间.jsonl`：发送侧完整记录。
- 同名 `.serial.json`：发送程序正常退出后的发送数量、替换数量、失败及重连统计。
- `sender_时间.log`：识别或回放程序输出，启动失败时查看这里。

原有 `启动USB识别.cmd` 默认仍只识别，不启用通信。

## 发送策略

识别与发送分线程，连接断开不停止识别和本地日志。默认最多每秒发送 10 帧，待发队列只保留最新结果，不积压旧位置。所有识别帧仍写本地日志。

`submitted` 为提交的识别帧数；`sent` 为写入完整包数量；`replaced` 为待发结果被新结果替换的数量；`failed` 为发送失败次数；`connect_errors` 为打开连接失败次数；`discarded_on_close` 为退出时舍弃的待发结果。主动限频和替换不属于接收端通信丢包。

当前是识别结果单向上传，没有控制指令、ACK 或重发旧位置。写入成功不等于下位机已经收到。序号只能发现两个已收到包之间的缺口，不能确定最后一包丢失，也不能推断监听之前漏了多少包。首次收到某个会话时以该包为序号基线。

## 数据协议 V2

实际串口默认 **460800、8N1、无流控**。物理两端参数必须一致，设备是否支持 460800 留待真实硬件验证；可以两端同时降低波特率和发送频率。本机模拟不验证这些参数。

```text
@<紧凑 ASCII JSON>*<4位十六进制 CRC>\n
```

`\n` 为实际换行字节 `0A`。CRC 为 **CRC-16/CCITT-FALSE**：多项式 `0x1021`，初始 `0xFFFF`，不反转，最终异或 `0x0000`。只计算 JSON 原始字节，不含 `@`、`*`、校验码和换行。标准输入 `123456789` → `29B1`。不能重新排版 JSON 后校验。单帧最大 16384 字节、最多 128 目标。

| 字段 | 含义 |
|---|---|
| `v` | 协议版本，固定 2，与本地日志版本分别管理 |
| `sid` | 发送会话编号；重连保持，重新启动发送器变化 |
| `s` | 通信发送尝试序号，从 1 开始 |
| `q` | 对应识别记录编号；限频时允许跳号 |
| `t` | 原识别记录的 UTC 时间；回放保留原值 |
| `wh` | 原始画面宽、高，像素 |
| `f` | 识别程序实际处理 FPS，首帧可为 0 |
| `ms` | 模型推理耗时，毫秒，不含整条流程 |
| `u` | 速度单位，目前 `null`；以后可为 `px/s`、`mm/s`、`cm/s` |
| `src` | `live_inference` 当前推理；`recording_replay` 历史回放 |
| `d` | 目标数组，无目标为 `[]` |

`d` 内每个目标固定 10 项：

```text
[目标ID, 物品类别ID, 垃圾大类代码, x, y, w, h, 置信度, 瞬时速度, 15次观测平均速度]
```

原点为画面左上角，x 向右、y 向下；x/y 为框左上角，w/h 为宽高，像素单位。目标 ID 在禁用跟踪时为 `null`；重新启动跟踪会重置 ID，应结合 `sid` 区分。当前暂定和已确认的 ID 都可发送，只发送本帧实际检测到的物体，不发送跟踪器内部丢失目标的预测框。

| 类别 ID | 物品 | 大类代码 |
|---|---|---|
| 0 | 瓷片 | O |
| 1 | 石子 | O |
| 2 | 砖块 | O |
| 3 | 纸杯 | R |
| 4 | 土豆 | K |
| 5 | 塑料瓶 | R |

大类 `H 有害垃圾 / R 可回收垃圾 / K 厨余垃圾 / O 其他垃圾`，当前模型没有有害垃圾目标。

接收器保存半帧缓存，支持拆分到达、多帧同时到达；检查 CRC 和字段格式，损坏帧丢弃并重新同步。重新连接时清空半帧。重复、乱序记录写日志但不更新表格；只按 `s` 统计通信序号缺口，不把 `q` 跳号算丢包。

## 接实际串口或其他助手

现在无需安装虚拟串口驱动。若将来使用仅支持 COM 的第三方串口助手，需要互连的两个串口，或一对虚拟 COM：识别程序打开发送端，助手打开另一端。两个程序不能同时占用同一个 COM 口来互相收发。第三方助手选择 ASCII/文本可查看原始 `@JSON*CRC`，本项目助手额外提供解码表格和统计。

有互连 COM5 → COM6 时，在两个独立终端分别运行：

```powershell
.\.venv\Scripts\python.exe scripts/serial_monitor.py --port COM6 --baudrate 460800
.\.venv\Scripts\python.exe scripts/run_live.py --serial-port COM5 --baudrate 460800 --serial-hz 10
```

无下位机的命令行演示，在两个独立终端分别运行：

```powershell
.\.venv\Scripts\python.exe scripts/serial_monitor.py --listen 8765
.\.venv\Scripts\python.exe scripts/run_live.py --serial-port socket://127.0.0.1:8765
```

同一监听端口一次开一份助手。摄像头已被其他识别窗口使用时先退出旧窗口；改摄像头编号可在识别命令追加 `--source 1`。本机默认只监听 127.0.0.1，无需互联网。
